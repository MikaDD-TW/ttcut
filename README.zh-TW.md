# ttcut

把一整段桌球比賽錄影變成節奏緊湊的成片：剪掉撿球、疊上常駐計分板，片尾再補一張數據統計看板。

[English](README.md) · **繁體中文**

單一個 Python 檔。不用安裝、不用註冊、不上傳，影片從頭到尾都待在你自己的電腦裡。

## 這個工具做什麼

回合標記一次做完，剩下的交給 ttcut：

- **剪掉空檔。** 從得分到下一次發球之間——撿球、走回來、擦汗——全部剪掉。四十分鐘的錄影通常會收到十二到十五分鐘。
- **燒上計分板。** 名字、局數、當局比分常駐在角落，數字由你的標記推導出來，不用另外手動輸入。
- **片尾收在統計看板。** 可選：凍結最後一格畫面，疊上各局比分表與雙方三個指標。

標記是刻意手動的。沒有球體追蹤會失準，也沒有模型要下載——發球按 `S`、得分按 `A` 或 `B`，速度跟看完整場比賽差不多。

## 環境需求

- **Python 3.8 以上**
- **ffmpeg**，而且要含 `libass`（畫計分板的 `subtitles` 濾鏡需要它）

```bash
# macOS
brew install ffmpeg

# Windows —— 到 https://www.gyan.dev/ffmpeg/builds/ 下載，
# 把 ffmpeg.exe 放在腳本旁邊，或用 --ffmpeg "C:\ffmpeg\bin" 指定資料夾

# Debian / Ubuntu
sudo apt install ffmpeg
```

ttcut 會依序找 `PATH`、腳本旁邊、Windows 常見安裝位置。找不到也還能標記和匯出 JSON，只是沒辦法算圖。

## 快速上手

```bash
python3 ttcut_v2_3.py
```

它會在 `127.0.0.1` 開一個本機服務並打開瀏覽器。接著：

1. **載入影片**——會跳出系統原生的檔案對話框（瀏覽器拿不到真實路徑，所以由 Python 來問）。
2. 填兩位選手的名字，選誰先發球。
3. 一邊播一邊標：發球觸拍的瞬間按 `S`，分數結束時按 `A` 或 `B`。
4. 想要片尾統計看板就勾 **數據統計**。
5. 按 **製作成片**。成品會放在來源影片旁邊，檔名是 `<原檔名>.cut.mp4`。

標記會同時存成 `<原檔名>.tags.json` 放在成片旁邊，之後要換參數重算，讀回來就好，不必重標。

### 快捷鍵

| 按鍵 | 動作 | 按鍵 | 動作 |
| --- | --- | --- | --- |
| `space` | 播放／暫停 | `←` `→` | 逐格 |
| `S` | 發球 | `⇧←` `⇧→` | 一秒 |
| `A` | A 得分 | `⌥←` `⌥→` | 五秒 |
| `B` | B 得分 | `1` `2` `3` `4` | 0.5×／1×／1.5×／2× |
| `N` | 換局 | `Z` | 復原最後一筆 |

點事件列表可以跳到該時間點，按 `×` 刪除。

## 賽制設定

| 設定 | 用途 |
| --- | --- |
| 每局 *n* 分 | 預設 11 分，要打舊制就填 21 |
| 標準／封頂 | 標準是要贏兩分。封頂制在 10:10 之後先到封頂分者勝，適合不想無限延長的球館規則 |
| 起始局數 | 一局一支影片、要接續前面局數時用 |
| 讓分 | 起始分數，可選每局套用或只套第一局 |

換發球是推導出來的，不用標：兩球換一次，deuce 之後每球換，新的一局由另一位先發。讓分的起始分不計入輪次，因為那幾分並沒有真的打。

## 數據統計看板

勾選 **數據統計** 之後，片尾會把最後一格畫面凍結住（預設 1 秒，可調），在中央疊上看板。角落的計分板會在此時收掉，把畫面讓出來；音軌同步補上等長的靜音，聲音和畫面長度不會對不上。

**上半部**是各局比分表，沿用轉播常見的排法：名字 → 總局數 → 各局分數。每一局贏的數字用亮色、輸的壓暗，總局數領先的一方用強調色。

**下半部**是左右對照：A 的數字在左、B 的在右，指標名稱置中。每一列比較好的一邊用強調色標出來。

| 指標 | 定義 |
| --- | --- |
| **總得分數** | 實際贏下的分數。讓分的起始分會顯示在計分板上，但不算在這裡——那不是打贏的。 |
| **發球得分率** | 自己發球時贏的分 ÷ 自己發球的分，原始分數寫在標籤旁邊。這是「由你開球時，你有多少把握」的數字。 |
| **最多連續得分** | 最長的連續得分，**跨局累計**。連兩局 11:0 就是 22，不是 11。 |

同一組數字在標記過程中就會即時顯示在右側欄，不必等算圖完才知道對不對。

有個前提值得記住：發球得分率的準確度完全取決於發球標記。漏標幾次 `S`，那幾分照樣算進總得分和連續得分，但輪次會跑掉，得分率也就跟著失真。

## 命令列

不想開介面、只想重算時用：

```bash
python3 ttcut_v2_3.py match.tags.json match.MOV
python3 ttcut_v2_3.py match.tags.json match.MOV --quality max --stats --stats-hold 3
python3 ttcut_v2_3.py match.tags.json match.MOV --dry-run      # 只印剪接表，不算圖
```

| 參數 | 預設 | 說明 |
| --- | --- | --- |
| `-o`, `--out` | `<影片>.cut.mp4` | 輸出路徑 |
| `--lead` / `--tail` | 讀 JSON | 發球前／得分後保留的秒數 |
| `--min-cut` | `2.0` | 短於此值就不剪，避免無意義的跳接 |
| `--cut-lets` / `--let-tail` | 關／`1.5` | 重發之間的撿球也剪掉 |
| `--stats` / `--no-stats` | 讀 JSON | 強制開啟或關閉統計看板 |
| `--stats-hold` | `1.0` | 看板停留秒數 |
| `--accent` | `#FF7A18` | 得分數字與名字左側裝飾條的顏色 |
| `--quality` | `high` | `fast`、`high`、`max`（走 libx264 CRF，慢很多） |
| `--encoder` | 依平台 | Mac 用 `h264_videotoolbox`；Windows 可用 `h264_nvenc`、`h264_qsv`、`h264_amf`、`libx264` |
| `--crf` / `--preset` / `--bitrate` | — | 直接覆寫畫質參數 |
| `--fps` | `source` | 預設跟著片源，也可以直接給數字 |
| `--hdr` | `auto` | `tonemap`、`keep`（需要 HEVC）、`ignore` |
| `--size` | 同片源 | 例如 `1920x1080` |
| `--hwaccel` | `auto` | Mac 用 `videotoolbox`，其餘 `none`、`cuda`、`qsv` |
| `--font` | 依平台 | 計分板名字用的字型 |
| `--ffmpeg` | — | `ffmpeg.exe` 的路徑或所在資料夾 |
| `--port` / `--no-browser` | — | 介面選項 |

完整清單請看 `--help`。

## 標記檔格式

匯出的就是純 JSON，可以直接手動改：

```jsonc
{
  "version": 2,
  "fps": 59.94,
  "players": { "A": "選手 A", "B": "選手 B" },
  "firstServer": "A",
  "format": { "pointsPerGame": 11, "deuce": "standard", "cap": 12 },
  "start": {
    "games":  { "A": 0, "B": 0 },
    "points": { "A": 0, "B": 0 },
    "handicapScope": "every"
  },
  "pads": { "tail": 1.0, "lead": 0.3 },
  "scoreboard": { "accent": "#FF7A18" },
  "stats": { "enabled": true, "hold": 1.0 },
  "events": [
    { "t": 12.35, "frame": 740, "type": "serve" },
    { "t": 18.90, "frame": 1133, "type": "point", "winner": "A" },
    { "t": 44.10, "frame": 2644, "type": "game" }
  ]
}
```

舊版本產生的檔案可以直接讀，缺少的區塊會自動退回預設值。

## 實作方式

- **剪接**用 ffmpeg 的 `select` 濾鏡篩選保留區間，而不是 `trim`+`concat`——後者會把整段解碼結果緩衝在記憶體裡。慢一些，但長片和 4K 不會爆掉。
- **計分板**產生成 ASS 字幕軌，再用 `subtitles` 濾鏡燒進畫面，所以任何解析度都能乾淨縮放，重畫也幾乎不花成本。
- **片尾凍結**是影像走 `tpad=stop_mode=clone`、音訊走 `apad`。
- **計分只有一份實作。** 瀏覽器完全不算分，它把事件丟給本機的 Python，再把回傳結果畫出來。只有一份邏輯，介面預覽和燒進去的計分板就不可能對不起來。
